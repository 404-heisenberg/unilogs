# Tech Stack

Every tool UniLogs depends on, and why it is there rather than the obvious
alternative. Where a choice was close, the runner-up is named.

## How the pieces fit

Three applications, deployed separately, talking over HTTP.

```
Browser
   │
   ▼
frontend/  React SPA on Vercel
   │  fetch, JSON
   ▼
backend/   Express API on Render ──► Google Calendar and OAuth, SendGrid
   │  Prisma
   ▼
PostgreSQL on Neon

docs/      Docusaurus site on Vercel (independent)
```

The frontend never touches the database. Every read and write goes through the
API. That separation is a requirement of the brief, but it also means the two
halves can be worked on by different people without stepping on each other.

## Repository

**One repository, three folders, no npm workspaces.**

A monorepo keeps the frontend and backend versioned together, so a change to an
API response and the change to the code consuming it land in the same pull
request. With seven people that matters more than the tidiness of separate repos.

We deliberately did not use npm workspaces. Workspaces hoist dependencies into a
single root `node_modules`, which is efficient but produces confusing failures
when two packages want different versions of the same library, and it complicates
deploying the two apps to different hosts. Four independent `package.json` files
cost some disk space and buy a much simpler mental model: every folder installs
and runs on its own.

## Frontend

| Tool               | Why this one                                                                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **React**          | The largest ecosystem and the one the team already knows. Time spent learning a framework is time not spent building features.                                                                                                                                |
| **TypeScript**     | Catches an entire class of bug before the code runs. With seven people editing shared code, types act as machine-checked documentation of what a function expects.                                                                                            |
| **Vite**           | Sub-second cold start and instant hot reload. Its predecessor, Create React App, is deprecated and no longer maintained.                                                                                                                                      |
| **Tailwind CSS**   | Styles live next to the markup, so there is no separate stylesheet to keep in sync and no naming conventions to argue about. It also removes the risk of one person's CSS quietly breaking another's page.                                                    |
| **shadcn/ui**      | Components are copied into our repository rather than installed as a dependency. We own the code and can change it. Built on Radix, so keyboard navigation and screen reader support are correct by default — which the accessibility criterion is marked on. |
| **React Router**   | The standard for client-side routing in React. Nothing exotic required.                                                                                                                                                                                       |
| **TanStack Query** | Everything that comes from the API. It handles caching, loading states, error states and refetching, which would otherwise be hand-written in every component and written slightly differently each time.                                                     |

**Server data lives in TanStack Query and nowhere else.** The little client-only
state the app has stays close to where it is used: component state for forms
and dialogs, and `localStorage` for the dashboard layout (read through React's
`useSyncExternalStore`, see `frontend/src/lib/dashboard.ts`). We planned to use
Zustand for this and Recharts for charts, but neither turned out to be needed.
The dashboard charts (heatmap, donut, bars) are small hand-built SVG components
that match the Figma designs exactly, so both libraries were removed in Sprint 3
rather than shipped unused.

### Supporting frontend packages

Smaller dependencies, pulled in to support the tools above rather than chosen as
standalone decisions:

| Package                                                                        | Why this one                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **radix-ui**                                                                   | The unstyled, accessible primitives shadcn/ui is built on. Handles focus trapping, keyboard navigation and ARIA attributes for components like dialogs and menus.                                                                                                                                                      |
| **class-variance-authority**                                                   | Defines the variant/size classes on generated shadcn/ui components (e.g. `button`'s `variant="outline"`). Required by the generator's own output, not chosen independently.                                                                                                                                            |

| **tw-animate-css**                                                             | Tailwind v4 has no built-in animation utilities. This restores the `animate-in`/`animate-out` classes shadcn/ui's generated components rely on, without pulling in a JS animation library.                                                                                                                             |
| **lucide-react**                                                               | Icon set. shadcn/ui's generated components and CLI assume Lucide icons by default, so using anything else means fighting the generator on every new component.                                                                                                                                                         |
| **@fontsource-variable/dm-sans**, **lora**, **cormorant-garamond**, **caveat** | The four typefaces in the Figma design system: DM Sans for the interface, Lora and Cormorant Garamond for headings, and Caveat for handwritten accents. | **next-themes**                                                                | Only because shadcn/ui's generated `sonner` wrapper reads the colour theme through it. UniLogs doesn't use it for anything else.                                                                                                                                                                                       |
| **react-markdown** + **remark-gfm**                                            | Renders the Markdown preview in the entry editor and on entry pages, including GitHub-flavoured extras such as task lists and tables. Renders to React elements rather than raw HTML, so entry text can't inject scripts.                                                                                              |
| **@tailwindcss/typography**                                                    | The `prose` classes that style rendered Markdown (headings, lists, quotes, code) consistently without hand-writing styles for every element.                                                                                                                                                                           |
| **@tailwindcss/vite**                                                          | Official first-party Vite plugin for Tailwind v4. Compiles Tailwind as part of Vite's own build graph instead of a separate PostCSS pass, which is how Tailwind v4 expects to be integrated.                                                                                                                           |
| **shadcn** (CLI)                                                               | Generates the components in `frontend/src/components/ui/` — see [Vendored code](#vendored-code) below. Not imported at runtime; used only via `npx shadcn add`.                                                                                                                                                        |

### Vendored code

`frontend/src/components/ui/` is not a dependency — it is third-party code
**copied into this repository** by the `shadcn` CLI rather than installed into
`node_modules`. Each file originates from [ui.shadcn.com](https://ui.shadcn.com),
is MIT-licensed, and is regenerated (never hand-edited) by running
`npx shadcn@latest add <component>`, per the gotcha in `AGENTS.md`.

It is documented here rather than left as an unexplained exception because it is
the one place in the codebase where third-party source, not just a third-party
package, lives directly in our tree. The tradeoff is deliberate: see the
shadcn/ui row above for why we accept owning and maintaining this code instead of
importing it as a black box.

## Backend

| Tool            | Why this one                                                                                                                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Express**     | Minimal and unopinionated. A heavier framework would impose structure we do not need and concepts the team would have to learn first.                                                                                                           |
| **TypeScript**  | Same reasoning as the frontend, with an extra benefit — Prisma generates types from the schema, so the database shape is checked at compile time.                                                                                               |
| **Prisma**      | Type-safe database access generated from a single schema file. Its migration system means schema changes are versioned in git and applied identically by everyone.                                                                              |
| **PostgreSQL**  | Relational, because our data is relational: users own entries, entries belong to projects, projects have tags. Also gives us JSON columns, which the customisable entry format needs.                                                           |
| **Neon**        | Serverless PostgreSQL with a usable free tier and database branching. No local database to install, so nobody loses a day to a broken Postgres setup.                                                                                           |
| **Better Auth** | Handles email and password, OTP-based email verification, password reset, sessions and Google OAuth in one library. The brief makes all of these compulsory, and hand-rolling authentication is the single easiest way to ship a security hole. |
| **Zod**         | Validates incoming request bodies and infers TypeScript types from the same schema, so validation and types cannot drift apart.                                                                                                                 |

### Supporting backend packages

| Package                           | Why this one                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **@prisma/adapter-pg** + **pg**   | Prisma 7's driver adapter mode. Prisma no longer bundles its own query engine binary for every database; instead it delegates connection handling to the standard `pg` driver via this adapter. Required for Prisma to talk to Neon at all under this version.                                                                                                     |
| **cors**                          | The frontend (Vercel) and backend (Render) are on different origins, so the browser blocks API requests without CORS headers. This middleware sets them for the frontend's allowed origin.                                                                                                                                                                         |
| **node-cron**                     | Runs the reminder sweep once an hour (`backend/src/scheduler.ts`): it finds projects that have gone quiet for longer than their reminder frequency, adds notifications and sends email digests. Runs inside the existing Express process, so reminders need no second service or paid scheduler. It is never started under test, so the suite stays deterministic. |
| **@scalar/express-api-reference** | Serves interactive API documentation ([`/api/docs`](https://unilogs.onrender.com/api/docs#description/introduction), live) generated from our OpenAPI spec, mounted directly as Express middleware. Chosen over Swagger UI for a more readable default theme with no extra configuration.                                                                          |
| **@sendgrid/mail**                | Sends every email UniLogs sends: verification codes, password reset links and reminder digests. Better Auth's callbacks only decide _when_ to send; something still has to deliver the message. See [External APIs](#external-apis), and [Considered and rejected](#considered-and-rejected) for why SendGrid over Resend.                                         |
| **dotenv** (dev only)             | Loads `.env` and `.env.test` into `process.env` for local development, Prisma commands and the test suite. Not used in production, where Render injects environment variables directly.                                                                                                                                                                            |

Password hashing is handled inside Better Auth, so there is no separate hashing library. An earlier version also used **bcryptjs** for password resets. It was removed in #238 after reset passwords turned out to be hashed differently from how sign-in verified them, so one library now owns both sides.

### A note on ESM

The backend uses native ES modules. This means relative imports carry a `.js`
extension even though the file on disk is `.ts`:

```ts
import { createApp } from './app.js';
```

This looks wrong and catches everybody once. It is documented in the backend
README because it is the most likely thing to block a new contributor.

## Documentation

**Docusaurus**, deployed to Vercel. Purpose-built for documentation sites,
supports MDX so React components can be embedded in pages, and gives us
versioning without configuration.

Search comes from **@easyops-cn/docusaurus-search-local**, which builds a
full-text index of every page at build time and searches it in the browser.
Docusaurus's built-in option, Algolia DocSearch, needs an application and an
external crawler. The local index needs no account or API key and works the
same on a laptop as on Vercel.

MDX matters for one specific reason: the course AI policy requires a declaration
on every page. A reusable `<AiDeclaration />` component means that declaration has
one definition and one format across the whole site, rather than being retyped
and gradually diverging.

## Tooling

| Tool                         | Why this one                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **ESLint**                   | Catches bugs that compile fine — unused variables, missing hook dependencies, unreachable code.                            |
| **Prettier**                 | Formatting is decided by a tool, so it is never discussed in a code review.                                                |
| **Husky**                    | Runs both of the above before a commit is created, so a formatting mistake cannot reach the repository in the first place. |
| **lint-staged**              | Restricts those checks to staged files, keeping the pre-commit hook fast enough that nobody is tempted to skip it.         |
| **Custom `commit-msg` hook** | Enforces our Scoped Commits format against ten frozen scopes.                                                              |

### Why we removed commitlint

Our original plan used commitlint. Its standard configuration,
`@commitlint/config-conventional`, enforces Conventional Commits — the
specification we deliberately rejected in favour of Scoped Commits. Configuring
it to accept our format and reject Conventional prefixes turned out to be more
work than a short shell script. We uninstalled it and wrote the hook directly.

This is worth recording because it is a case where the popular tool was the wrong
tool, and the simpler option was better.

## Testing

| Tool                      | Why this one                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Vitest**                | Vite-native test runner. Reuses Vite's own TypeScript/JSX transform pipeline instead of a separate Jest config that has to be kept in sync, and runs on both frontend and backend so the team learns one runner, not two.                                                                                                                                                  |
| **React Testing Library** | Queries components the way a user finds them — by role, label, and visible text — rather than through internal component state. Catches real usability regressions and survives refactors that break tests written against implementation details.                                                                                                                         |
| **Supertest**             | Drives the real Express app over HTTP from inside a test rather than calling route handlers directly, so backend tests exercise the same middleware, auth, and validation pipeline that runs in production.                                                                                                                                                                |
| **Playwright**            | The layer above component tests: drives a real browser against the real frontend and backend together. Chosen over Cypress for first-party TypeScript support and because its own config can launch multiple dev servers directly (see `frontend/playwright.config.ts`), which fits this repo's two-server, no-workspaces layout without extra process-management tooling. |
| **@vitest/coverage-v8**   | Measures coverage for both the frontend and backend suites using V8's built-in instrumentation, so no separate code transform is needed. Every `npm test` run reports it, and CI fails if it drops below the thresholds in [Testing Policy](/testing-policy).                                                                                                              |

Three layers, each catching what the one below it cannot: Vitest unit tests
check logic in isolation, the component/integration tests above check that a
page or route behaves correctly against a mocked or real dependency, and
Playwright checks that signing up, creating a project, and logging an entry
actually works end to end against a real backend and database. Playwright is
deliberately the smallest suite — it is the slowest layer, so it is reserved
for the golden path and the failure modes that only exist once a real backend
is in the loop, such as a duplicate email or a wrong password rejected by the
database rather than a mock.

## Deployment

| What     | Where  | Why                                                                                                                 |
| -------- | ------ | ------------------------------------------------------------------------------------------------------------------- |
| Frontend | Vercel | Zero-config for Vite, deploys on push, preview URLs for every pull request.                                         |
| Docs     | Vercel | Same pipeline, no second platform to learn.                                                                         |
| Backend  | Render | Free tier that runs a long-lived Node process. Vercel's serverless model does not suit a persistent Express server. |
| Database | Neon   | Managed, free tier, no local installation.                                                                          |

Render's free tier spins a service down after inactivity, which adds a cold-start
delay to the first request. A scheduled GitHub Actions workflow
(`.github/workflows/keep-warm.yml`) pings `/api/health` every 10 minutes to keep
the service warm. See [Performance](/performance#uptime-and-the-first-request).

## External APIs

UniLogs calls three third-party APIs. Every call is made from the backend, so no
API key or OAuth secret ever reaches the browser.

| API                                                                   | What UniLogs uses it for                                                            | Data involved                                                                                                 | If it is unavailable                                                                                                                                                          |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **[Google Calendar API](https://developers.google.com/calendar/api)** | Turning upcoming events into entry suggestions, and the dashboard's Upcoming widget | Read-only (`calendar.readonly` scope). The next 30 days of the user's **primary** calendar, at most 20 events | The Suggestions page and Upcoming widget show an error with a **Try again** button. The rest of the app is unaffected.                                                        |
| **Google OAuth 2.0**                                                  | "Sign in with Google", and the consent step that grants calendar access             | The user's name and email address. The calendar scope is requested only when they connect their calendar      | Google sign-in is unavailable. Email and password sign-in, the primary login method, still works.                                                                             |
| **[SendGrid Mail API](https://www.twilio.com/docs/sendgrid)**         | Sending verification codes, password reset links and reminder digests               | The recipient's email address and the message                                                                 | The send is logged and skipped rather than crashing the request. Locally, without a SendGrid key, emails are printed to the console instead, so development needs no account. |

**Why Google Calendar.** Students already keep their timetable there. Pulling
scheduled events in means log entries can be created from something that already
happened rather than typed from memory, which removes most of the friction the
brief describes with the physical logbook.

**Why OAuth is separate from sign-in.** Connecting a calendar is optional and
separate from the compulsory email and password authentication, which remains
the primary login method. A user who signs up with email can still connect
Google Calendar later from **Settings**.

**Known limitation.** Only the primary calendar is read. Testers asked for
multiple calendars (see [User Testing](/user-testing)). Supporting them means
listing the user's calendars and merging their events, which is the first
follow-up for this integration.

## Considered and rejected

| Instead of        | We considered              | Why not                                                                                                                                                                                                                                                                                                                                  |
| ----------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vite              | Next.js                    | Server-side rendering solves problems a logged-in tool does not have, and adds deployment complexity.                                                                                                                                                                                                                                    |
| Tailwind          | CSS Modules                | Slower to write and needs naming discipline across seven people.                                                                                                                                                                                                                                                                         |
| shadcn/ui (Radix) | Base UI                    | Newer and shadcn's current recommendation, but Radix has years of existing answers online, which matters more when six people are learning at once.                                                                                                                                                                                      |
| Component state   | Zustand, Redux Toolkit     | Redux has more boilerplate than our state justifies. We planned Zustand for UI state, but the only shared client state turned out to be the dashboard layout, which `localStorage` handles. Zustand was removed unused.                                                                                                                  |
| Hand-built SVG    | Recharts                   | Planned for the statistics charts. The Figma charts (heatmap, donut, bars) are simple enough that hand-built SVG matches them exactly and ships no extra JavaScript. Recharts was removed unused.                                                                                                                                        |
| Prisma            | Drizzle, raw SQL           | Drizzle is lighter but less familiar; raw SQL gives up type safety.                                                                                                                                                                                                                                                                      |
| Better Auth       | Auth.js, hand-rolled       | Auth.js is Next-oriented. Hand-rolling authentication is not a risk worth taking.                                                                                                                                                                                                                                                        |
| Docusaurus        | Markdown in the repository | Rejected on the grounds that the brief asks for a publicly accessible site with non-trivial content.                                                                                                                                                                                                                                     |
| Express           | Fastify, NestJS            | Fastify is faster but the difference is irrelevant at our scale; NestJS imposes a learning curve for structure we can add ourselves.                                                                                                                                                                                                     |
| Playwright        | Cypress                    | Both are solid; Playwright's config-driven multi-server startup better fits our two-server, no-workspaces layout, and its TypeScript support needs no extra setup.                                                                                                                                                                       |
| SendGrid          | Resend                     | Resend only sends to arbitrary recipients once a domain is verified, and this project only has a free `*.vercel.app` subdomain, whose DNS Vercel controls, not us — so it can't be verified. SendGrid's Single Sender Verification needs just one confirmed email address, no domain ownership, so it actually reaches whoever signs up. |
