# API Overview

The UniLogs backend is a hand-written Express API, deployed separately from the
frontend on Render. This page is a map of every endpoint. For request and
response schemas, and to try a request in the browser, use the live reference:

**[Open the interactive API reference →](https://unilogs.onrender.com/api/docs)**

The reference is generated from the OpenAPI 3 spec in `backend/src/openapi.ts`,
and the raw spec is served at
[`/openapi.json`](https://unilogs.onrender.com/openapi.json). The tables below
list the same endpoints as that spec. In the live reference each section below
is a group with its own tag, so you can jump straight to it with an anchor like
`#tag/Entries/get_entries`.

## Conventions

- **Base URL:** `https://unilogs.onrender.com`
- **Authentication:** every `/api/*` endpoint except sign-up, sign-in, password
  reset, Google sign-in and health needs a signed-in session. Better Auth sets the session as a
  cookie on sign-in. Requests without one get `401`.
- **Ownership:** users only ever see their own projects, entries, tags and
  notifications. Asking for someone else's resource returns `404`, not `403`, so
  the API doesn't reveal that it exists.
- **Errors:** `400` for invalid input (with a message saying which field),
  `401` when not signed in, `404` when the resource doesn't exist or isn't
  yours.
- **Soft delete:** deleting an entry is reversible — it moves to the project's
  trash instead of being destroyed. Every read path excludes trashed entries
  unless the endpoint is explicitly about them.
- **Public endpoints:** `/share/*` needs no account, so a supervisor can open a
  report link. These endpoints are rate-limited and return `429` when the limit
  is hit.

| ------ | --------------------------- | ------------------------------------- |
| POST   | `/api/auth/signup`          | Create an account with email/password |

| POST   | `/api/auth/forgot-password` | Email a password reset link           |

## Projects

| POST   | `/api/projects`                 | Create a project                                             |
| GET    | `/api/projects/{id}`            | Get a project                                                |

## Fields

Each project defines its own entry fields (text, number, duration, toggle,
date). Entry content is validated against these definitions.

| Method | Path                                    | What it does                |
| ------ | --------------------------------------- | --------------------------- |
| GET    | `/api/field-definitions?projectId={id}` | List a project's fields     |
| POST   | `/api/field-definitions`                | Add a field to a project    |
| GET    | `/api/field-definitions/{id}`           | Get a field                 |
| PUT    | `/api/field-definitions/{id}`           | Rename a field or change it |
| DELETE | `/api/field-definitions/{id}`           | Remove a field              |

## Entries

| Method | Path                                             | What it does                                                                            |
| ------ | ------------------------------------------------ | --------------------------------------------------------------------------------------- |
| GET    | `/api/entries`                                   | List entries, paged. Filters: `q` (search), `projectId`, `tagIds`, `dateFrom`, `dateTo` |
| POST   | `/api/entries`                                   | Log an entry: date, title, Markdown body, field values and tags                         |
| GET    | `/api/entries/{id}`                              | Get an entry                                                                            |
| PUT    | `/api/entries/{id}`                              | Update an entry (every change is written to the audit log)                              |
| DELETE | `/api/entries/{id}`                              | Soft-delete an entry — it moves to the project's trash                                   |
| GET    | `/api/entries/{id}/history`                      | Every recorded version of an entry, newest first (append-only)                          |
| POST   | `/api/entries/{id}/history/{auditId}/restore`    | Restore an earlier version (writes a *new* version, never rewrites history)             |
| POST   | `/api/entries/{id}/restore`                      | Bring an entry back from the trash                                                      |
| GET    | `/api/entries/as-at`                             | Read-only reconstruction of the logbook as it stood on a given date                     |
| POST   | `/api/entries/sync`                              | Sync a queue of offline-created entries, idempotent by `clientId`                       |

## Statistics

| Method | Path                                                      | What it does                                                       |
| ------ | --------------------------------------------------------- | ------------------------------------------------------------------ |
| GET    | `/api/stats`                                              | Totals across all projects, with a per-project breakdown           |
| GET    | `/api/stats/frequency`                                    | Entries per week and per term                                      |
| GET    | `/api/stats/streak`                                       | Current logging streak in days                                     |
| GET    | `/api/stats/unfinished`                                   | Open to-do fields: overdue, due this week, no due date             |
| GET    | `/api/stats/fields/{projectId}`                           | Per-field insights for one project (totals, averages, trends)      |
| GET    | `/api/projects/{id}/stat-panels`                          | List a project's stat panels with their computed values            |
| POST   | `/api/projects/{id}/stat-panels`                          | Create a stat panel from an arithmetic expression                  |
| POST   | `/api/projects/{id}/stat-panels/preview`                  | Evaluate an expression without saving                              |
| PATCH  | `/api/projects/{id}/stat-panels/{panelId}`                | Rename, re-order, or re-scope a stat panel                         |
| DELETE | `/api/projects/{id}/stat-panels/{panelId}`                | Delete a stat panel                                                |
| GET    | `/api/stat-panels`                                        | Every panel across the user's active projects, with computed values |

Custom stat panels evaluate an arithmetic expression (`+ - * / ( )`) over a
project's numeric fields, **server-side and without `eval`**, then aggregate
the per-entry results with Sum or Average over a date range.

## Export and sharing

| Method | Path                                       | What it does                                              |
| ------ | ------------------------------------------ | --------------------------------------------------------- |
| GET    | `/api/export`                              | Download a project's entries as CSV or Markdown           |
| POST   | `/api/projects/{id}/share-links`           | Create a read-only share link for a project report        |
| DELETE | `/api/projects/{id}/share-links/{token}`   | Revoke a share link                                       |
| GET    | `/share/{token}`                           | **Public.** The read-only report behind a share link      |
| GET    | `/share/{token}/export`                    | **Public.** Download the shared report as CSV or Markdown |

Share links let a supervisor or collaborator read a report without an account.
The `/share/*` routes are the only endpoints that skip authentication.

## Google Calendar

| Method | Path                                                | What it does                                              |
| ------ | --------------------------------------------------- | --------------------------------------------------------- |
| GET    | `/api/calendar/status`                              | Whether the user's Google Calendar is connected           |
| POST   | `/api/calendar/connect`                             | Start the Google consent flow                             |
| DELETE | `/api/calendar/disconnect`                          | Disconnect Google Calendar                                |
| GET    | `/api/calendar/sources`                             | List the user's connected calendars                       |
| PATCH  | `/api/calendar/sources/{id}`                        | Enable/disable a calendar or change its colour            |
| GET    | `/api/calendar/events`                              | Upcoming events from the user's connected calendars       |
| GET    | `/api/calendar/events/suggestions`                  | Events not yet logged, offered as entry suggestions       |
| POST   | `/api/calendar/events/suggestions/{eventId}/accept` | Turn a suggestion into an entry                           |
| POST   | `/api/calendar/events/suggestions/{eventId}/reject` | Dismiss a suggestion                                      |

UniLogs can read **more than one Google calendar** (lectures, tutorials,
personal). Each calendar is a `CalendarSource` the user can enable, disable and
colour from Settings; suggestions and events respect that choice. Google event
IDs are only unique within a calendar, so suggestions key on calendar *and*
event.

## Deleted and trashed entries

| Method | Path                       | What it does                                                        |
| ------ | -------------------------- | ------------------------------------------------------------------- |
| GET    | `/api/projects/{id}/trash` | List a project's deleted entries, ready to restore or review        |

Deleted entries are soft-deleted (`Entry.deletedAt`): they vanish from normal
reads, appear in the trash, and can be restored. This sprint ships **no
permanent delete** — the record is hard to lose.
